# Local CSV Data Guide

Snapshot date: 2026-07-29

This guide explains where the local CSV files belong, what each file contains,
and how the election-arbitrage pipeline uses them. The accompanying archive
stores the files under `latest_snapshot/` using the same relative paths expected
by the repository.

## Important Data Boundary

The repository has two execution boundaries:

1. Stage 0-1 data construction starts from a manually supplied Bloomberg export
   and uses SEC, WRDS, and Anthropic access plus manual identifier review.
2. The reproducible offline Stage 2-10 run starts after the seven required input
   CSVs listed below have been placed in the repository.

A fresh GitHub clone does not contain most of these files because licensed,
large, and generated data are intentionally gitignored.

Some files in this package contain or derive from Bloomberg and WRDS data.
Recipients are responsible for complying with the applicable data licenses.
Do not commit the local snapshot to a public repository.

## Install the Snapshot

Unzip the package, then copy the contents of `latest_snapshot/` into the project
root while preserving directories:

```bash
cd /path/to/JPM-Project-3ii
cp -R "/path/to/JPM_Project_3ii_Data_2026-07-29/latest_snapshot/." .
```

Confirm that the seven required inputs are in the expected locations:

```bash
python3 arb_pipeline.py check
```

Rebuild all offline analytics, strategy outputs, and presentation material:

```bash
python3 arb_pipeline.py fast
```

`fast` overwrites the generated root-level output CSVs and the files under
`material/`. It does not call Bloomberg, SEC, WRDS, or Anthropic.

## Join Keys and Units

- `event_id` is the primary event join key across terms, outcomes, labels,
  signals, market histories, and presentation tables.
- `side` distinguishes target and acquirer market observations.
- Dates are stored as parseable date strings and should be interpreted in
  calendar order, not row order.
- Probability columns such as `p_completed` use fractions from 0 to 1.
- Columns ending in `_%` are percentage values, not decimal fractions.
- Raw daily-return columns in `arb_strategy_daily_returns.csv` and
  `arb_strategy_event_daily_returns.csv` are decimal fractions.
- Notional and P&L fields are US dollars unless the column explicitly states
  another unit.
- Blank fields generally mean the source disclosure, price path, or model input
  was unavailable; they should not automatically be treated as zero.

## Integrity

`SHA256SUMS.txt` in the archive records a checksum for `data.md` and every
packaged CSV. Use it from the unzipped package root:

```bash
shasum -a 256 -c SHA256SUMS.txt
```
